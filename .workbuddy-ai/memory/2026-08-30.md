## ChatDev real sprite swap (latest commit)

User pointed out that hand-coded ASCII grids can never match professional
pixel art - the previous top-down rebuild looked like a different game.
Looked at how ChatDev actually does it (OpenBMB/ChatDev, Apache-2.0):

  * 144 pre-rendered PNGs at
    frontend/public/sprites/{1-12}-{D,L,R,U}-{1,2,3}.png
  * each PNG is one character pose (508x847 transparent, ~85KB)
  * their spriteFetcher.js swaps the <img> src to animate
  * the "characters" are not hand-coded - they're shipped as art

Adopted the same approach:

  * scripts/fetch_chatdev_sprites.py - downloads all 144, prints
    per-character colour profiles
  * scripts/build_sprite_sheet.py - crops to per-character union alpha
    bbox (so walk cycle doesn't jitter), fits into 28x44 cells preserving
    the source 0.6 aspect ratio with bottom-centre anchoring, quantises
    to 64 colours, composites a 336x264 sheet, emits base64
  * scripts/use_chatdev_sprites.py - inlines the sheet, collapses BODY_*
    grids to {role:"X"} markers (so npcs / PERSONAS / SPEAKER_BODY /
    player.body all keep working untouched), replaces drawActor with a
    blit, rewrites the feed avatar to blit, replaces the row-width boot
    validator with a sheet-size check
  * app/assets/NOTICE carries Apache-2.0 attribution to OpenBMB

Role -> ChatDev character (chosen for colour separation):
  KEEPER=4 gold   PROF=2 purple   GUARD=5 navy
  RITIKA=1 cyan   MEERA=3 cream   ARJUN=8 brown

Live confirmed: https://r2-d2.xyz/demo/ - LIVE, chain OK seq 680, zero
page errors, real ChatDev characters visible (purple-haired MEERA,
cyan/blue RITIKA, etc).

Key insight: when a reference image shows professional pixel art, the
right approach is the source art, not a hand-coded reproduction. ASCII
grids are for tile maps / props, not characters.
## Stage rebuild (user: "character are good now, can you also change the
## stage ... rest all things are good")

ChatDev ships NO tileset (frontend/public/ has only sprites/ + media/),
so the room had to be hand-built. That is legitimate here, unlike the
characters - there is no source art to copy.

Root cause of "the stage is cold": buildMap() fills all 30x20 tiles with
"#" and drawTile() routed "#" -> floorRunner(), so the ENTIRE floor was
teal carpet. Hue histogram: C(cyan) 1002, B(blue) 555, O(wood) 513.
Fix: "#" -> floorWood, carpet is now an explicit "r" tile.
After: O(brown) 82%, cyan gone.

scripts/build_stage.py (idempotent, patches from anchors):
  * oak plank floor - 2x8px bands/tile, alternate bands staggered 8px
  * checkered rug - checkers aligned to WORLD coords and clipped to the
    inner rect (a naive inset makes border tiles' checkers ragged and out
    of step with interior tiles); fringe on unshared edges
  * pool with a stone kerb only where water meets land
  * pale lime plaster walls (deliberately much lighter than the oak floor
    or room edges become unreadable - sandstone and oak share a hue)
  * 32 props depth-sorted with actors: plant/lamp/crate/barrel/shelf/
    chalkboard/monitor/sign
  * floating pxText labels -> wooden plaque signs on posts
  * prof was parked inside a wall column (x=9 is "W" for y=2..19);
    moved to open plaza (17,8)

BUG PATTERN worth remembering: hash2(x,y) = ((x*73+y*151)%97+97)%97 is a
LINEAR form, so it collapses whenever the two args move on a fixed
lattice. hash2(9i, 4i+3) == 65 for every i (because 1261 == 13*97). It
looked fine for (tx,ty) floor tiles but flattened the monitor's code
lines to 4 identical bars and made every shelf book the same width.
Replaced with an avalanche mix (Math.imul-based).

scripts/inspect_stage.py [lum] - the ONLY way to see pixel art
headlessly. Hue mode answers "is the palette warm/cold"; greyscale mode
answers "is the geometry right". Plank seams were invisible in hue mode
(every wood shade is one bucket) and obvious in lum mode.

### Two bugs found and fixed by testing rather than reading
1. **CRLF would silently break rollback.** A CRLF checkout puts a trailing
   \r on the remote backup path parsed out of the piped apply script, so
   rollback fails on a nonexistent path. Fixed by CR-stripping the embedded
   heredoc, stripping the parsed BACKUP path defensively, stripping \r in
   env_get_*, and pinning *.sh to LF in .gitattributes.
2. **A bash test of my own was wrong**, not the code: `$"\r"` is locale
   translation syntax, not ANSI-C quoting. Use `$'\r'`. Cost me a cycle.
