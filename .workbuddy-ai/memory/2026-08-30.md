## ChatDev real sprite swap (latest commit)

User pointed out that hand-coded ASCII grids can never match professional
pixel art - the previous top-down rebuild looked like a different game.
Looked at how ChatDev actually does it (OpenBMB/ChatDev, Apache-2.0):

  * 144 pre-rendered PNGs at
    frontend/public/sprites/{1-12}-{D,L,R,U}-{1,2,3}.png
  * each PNG is one character pose (508x847 transparent, ~85KB)
  * their spriteFetcher.js swaps the <img> src to animate
  * the "characters" are not hand-coded - they're shipped as art

Adopted the same approach:

  * scripts/fetch_chatdev_sprites.py - downloads all 144, prints
    per-character colour profiles
  * scripts/build_sprite_sheet.py - crops to per-character union alpha
    bbox (so walk cycle doesn't jitter), fits into 28x44 cells preserving
    the source 0.6 aspect ratio with bottom-centre anchoring, quantises
    to 64 colours, composites a 336x264 sheet, emits base64
  * scripts/use_chatdev_sprites.py - inlines the sheet, collapses BODY_*
    grids to {role:"X"} markers (so npcs / PERSONAS / SPEAKER_BODY /
    player.body all keep working untouched), replaces drawActor with a
    blit, rewrites the feed avatar to blit, replaces the row-width boot
    validator with a sheet-size check
  * app/assets/NOTICE carries Apache-2.0 attribution to OpenBMB

Role -> ChatDev character (chosen for colour separation):
  KEEPER=4 gold   PROF=2 purple   GUARD=5 navy
  RITIKA=1 cyan   MEERA=3 cream   ARJUN=8 brown

Live confirmed: https://r2-d2.xyz/demo/ - LIVE, chain OK seq 680, zero
page errors, real ChatDev characters visible (purple-haired MEERA,
cyan/blue RITIKA, etc).

Key insight: when a reference image shows professional pixel art, the
right approach is the source art, not a hand-coded reproduction. ASCII
grids are for tile maps / props, not characters.
